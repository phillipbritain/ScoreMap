# Planned game length and estimated end times

ESPN's scoreboard says when a game starts but not when it ended, yet the Final pin window depends on that time: a Final game keeps its pin for 5 minutes after it ends (ADR-0021; 2 hours when this was decided). So each league is configured with a `PlannedLength`, how long its games usually take, and the server works out the missing time itself. A game the server sees turn Final ended when it was first seen so. A game already Final the first time the server sees it, for instance after the server slept with no browser connected, gets an estimated end of its start plus `PlannedLength`, or now if that is still to come; otherwise old games would reappear for the Final window every time the server woke. (Disrupted games once kept the windows of their original schedule, or of their suspension, by the same estimates; since ADR-0021 they aren't shown at all.) We accept that these estimates are wrong for long overtimes and short games, and that the game panel shows the estimate as the end time. A provider that reports real end times would make this unnecessary.
