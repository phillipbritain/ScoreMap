# Scenarios for local runs: a fake feed in the server, picked in the app, at real venues

Run locally, ScoreMap shows a Scenario by default rather than real games, so its look and its live updates can be checked at any time without waiting for real games to start; real ESPN data matters mostly on the deployed site, and stays one choice in the picker. The made-up games come from a fake game feed provider in the server, in place of ESPN's (ADR-0001), rather than from a fake ESPN server or from fakes in the browser: everything after the feed (the game board's statuses, windows and change events, the venue locator, the poller and the hub, and the browser app) is the real code, and scenarios are written as JSON in ScoreMap's own terms rather than in ESPN's unofficial response shape. Scenarios exist only when the server runs in Development, so the deployed site can never show made-up scores. The default comes from `appsettings.Development.json` (or `dev.ps1 start -Scenario`), and a floating picker over the globe switches between scenarios, and to real games, while running. Because the server holds one set of games for every browser, it runs one scenario at a time, and switching it in one tab switches it in all of them; per-tab scenarios would have needed a game board per connection, for testing alone.

Scenarios use real venues, from a hand-written list in the repo, so pin placement is tested on real places; their lookups are made once by a script and checked into the repo rather than made through Nominatim at runtime, which at one lookup per second would take minutes for the default scenario on every new machine. The price is a file to regenerate when the venue list changes, and scenario pins don't exercise a live Nominatim lookup.

## Consequences

- With the poller's real intervals (15 s while a league has Live games, 3 min otherwise) a scripted change would show up to minutes late, so in scenario mode every league is fetched every second; the poller's code path is unchanged.
- A looping script restarts with fresh copies of its games under new ids, and the old copies drop out of the feed, so no game ever goes back from Final to Live; random play likewise retires Final games and adds new ones, rather than letting games run forever.
- Scenario times are relative to when the scenario starts, on the real clock; the server's `TimeProvider` is never sped up, since the poller, the Nominatim rate limit and the pin windows all share it.
